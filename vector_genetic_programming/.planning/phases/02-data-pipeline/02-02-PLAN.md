fit_transform(ohlcv: dict[str, pd.DataFrame]) -> np.ndarray:

Step 1 — Build aligned close prices DataFrame (one column per asset) to determine which assets have sufficient data:
```python
closes = pd.DataFrame({ticker: df["close"] for ticker, df in ohlcv.items()})
closes = closes.sort_index()
closes = closes.ffill(limit=self.max_fill_days)
min_obs = int(self.min_obs_fraction * len(closes))
n_valid = closes.notna().sum()
keep = n_valid[n_valid >= min_obs].index.tolist()
dropped = [c for c in closes.columns if c not in keep]
if dropped:
    logger.info("Dropping assets with insufficient data: %s", dropped)
self.dropped_assets_ = dropped
self.retained_assets_ = keep
logger.info("Asset filter: %d/%d assets retained", len(keep), len(closes.columns))
```

Step 2 — For each retained asset, compute all 12 features into a single DataFrame. Use only ohlcv[ticker] columns (open, high, low, close, volume). All arithmetic uses pandas operations on the DataFrame, then convert to numpy at the end only. Use .copy() before mutation. Use .to_numpy() not .values. Use .loc[] for assignment.

Feature formulas:
- ret_1d: close.pct_change(1)
- ret_5d: close.pct_change(5)
- ret_20d: close.pct_change(20)
- log_close: np.log(close)
- vol_5d: close.pct_change(1).rolling(5).std()
- vol_20d: close.pct_change(1).rolling(20).std()
- atr_14: rolling 14-period mean of (high - low).abs()  [simplified ATR; true ATR requires prev close but introduces complexity; use high-low range]
- parkinson_14: rolling 14-period mean of (np.log(high/low) ** 2 / (4 * np.log(2))) ** 0.5 (Parkinson volatility estimator using log(high/low))
- rsi_14: 14-period RSI computed as: delta = close.diff(); up = delta.clip(lower=0).rolling(14).mean(); dn = (-delta).clip(lower=0).rolling(14).mean(); rsi = 100 * up / (up + dn)  [handle division by zero: where (up + dn) == 0, rsi = 50.0]
- norm_close: (close - close.rolling(20).min()) / (close.rolling(20).max() - close.rolling(20).min())  [clip to [0,1]; handle division by zero: where max == min, norm_close = 0.5]
- vol_ratio_20d: volume / volume.rolling(20).mean()  [handle division by zero: where mean == 0, vol_ratio = 1.0]
- obv_signal: sign of pct_change(1) * volume, then cumsum, then z-score normalize per asset (subtract mean, divide by std; if std == 0, output 0)

Step 3 — Assemble per-asset feature DataFrame with columns in this exact order:
['ret_1d', 'ret_5d', 'ret_20d', 'log_close', 'vol_5d', 'vol_20d', 'atr_14', 'parkinson_14', 'rsi_14', 'norm_close', 'vol_ratio_20d', 'obv_signal']

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| raw OHLCV data -> feature computation | High/low values could be negative or zero (malformed parquet); log and division operations would produce NaN or inf |
| feature array -> downstream GP | NaN or inf in the array propagates silently through GP tree evaluation; the NaN check (D-08) is the guard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | FeatureEngine NaN check | mitigate | ValueError raised explicitly if NaN persists after trim; prevents silent bad-data propagation to GP layer |
| T-02-05 | Elevation of Privilege | WalkForwardSplitter | mitigate | AssertionError on ordering violation is the structural enforcement (D-11); the test set is never reachable if the splitter raises at config time |
| T-02-06 | Information Disclosure | lookback trim | accept | Trim is applied after ffill; residual NaN from genuine data gaps raises ValueError with diagnostic message |
</threat_model>
